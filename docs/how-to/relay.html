Set Up Field Day Commander Relay

Send contacts from your logging PCs to a server on another network.

How-To Guides › Field Day Commander Relay
Logging · Optional

Use Field Day Commander Relay to send contacts from your logging software to Field Day Commander, even when the server is at a member's house or hosted on the internet. It's a Windows desktop program that runs on a logging computer and collects contacts from that PC or other PCs on your club LAN. It connects out to the server over HTTPS, so you don't need to forward ports.

Do You Need the Relay?

If you answer yes to any of these questions, you need the relay:

  • Is your server on a different network from your logging PCs, such as at a member's house or hosted online?
  • Does your logger only write an ADIF log file?
  • Do you want N3FJP PCs to keep logging if the link to the server drops?
  • Does your club already run an N3FJP network server PC you want to keep?

The relay saves every contact on disk on the logging computer before sending. It keeps collecting while the internet or server is down, then sends the waiting contacts when the connection returns without creating duplicates. It sends over HTTPS and checks the server's certificate. A self-signed club certificate works once you confirm the server's key matches with whoever runs it. All connections to the server are outbound, so you don't need port forwarding. You connect with a one-time enrollment code, which gives the relay its own token. You can revoke that token on the server's Relays page.

You don't need the relay if your server and logging PCs share the club LAN and Logging > External Loggers covers your logger. You also don't need it if everyone logs in the browser.

What You Need

  • A logging PC running 64-bit Windows 10 or later.
  • A server running Field Day Commander 26.11.2 or later, reachable over HTTPS from that PC. For a public server, see DNS & TLS.
  • A current event with the right dates. For testing, use a practice event whose dates cover the test.
  • A server account with enroll-relays permission. All four default roles have it.

If your server runs on Windows, see Using Field Day Commander Relay for connection options.

Step 1: Install the Relay

  1. Download relay-setup.exe from the Download page. Choose relay-portable.exe for a borrowed PC. Checksums are in SHA256SUMS.
  2. Run the download. For the portable version, put it in a folder you can write to first.

The downloads aren't code signed yet. If SmartScreen warns, click More info, then Run anyway, only for a file downloaded from the Download page.

The installer runs for your Windows account without admin rights or a folder choice. On its last page, Start the relay now is checked. Start the relay when I sign in to Windows is unchecked unless already configured. Only one relay can run per computer.

Keeping or removing the relay

To update, run the new installer. It keeps saved contacts and your connection. N1MM broadcasts sent while the relay is closed are lost. Recover them with Tools > Rebroadcast all Contest QSO's to other Apps in N1MM Logger+.

Uninstall through Windows' Apps list. Data stays behind. Click Disconnect first if you also want to remove the token. For the portable version, wait until Waiting is zero before deleting the program and its relay-data folder.

Step 2: Create an Enrollment Code

  1. Open Logging > Relays on the server.
  2. Enter a Relay name, such as "Phone tent laptop".
  3. Click Create Code.

The page shows Server address and Enrollment code, with a copy button for the code. It works once, expires in 15 minutes, and belongs to the current event. The relay shows as Waiting to enroll.

Step 3: Connect to the Server

  1. Enter the server's Server address in the relay's Connect to your server card.
  2. Paste the Enrollment code.
  3. Click Connect.

If the relay shows Server's key instead of connecting, your server uses a self-signed certificate. Ask whoever runs the server to confirm the key before you click The keys match, connect, using Self-Signed Certificates below.

Look for Connected in the relay. The server's Relays page changes to Enrolled and shows when it was last seen and its version. Use Revoke there to stop accepting contacts from it.

The portable version keeps data in relay-data beside the program, but its token stays in this PC's Windows keychain. Moving it to another PC requires a new code. To change events, click Disconnect and connect with a code for the new event.

Step 4: Pick a Station

Choose your station from Station in the Server connection card. If offered, use New station to enter a New station name, then click Use new station.

Each contact gets its station in this order:

  1. If Use this station for all contacts is on, every contact uses the picked Station. Turn this on only when every PC sending through the relay belongs to that station.
  2. Otherwise, it keeps the name from its logger. N3FJP uses This Station's Name or the PC's computer name. N1MM Logger+ uses the logging PC's computer name. WSJT-X/JTDX uses its --rig-name if set. Without that, another PC gets WSJT-X @ IP or JTDX @ IP. ADIF over UDP from another PC gets STATION_CALLSIGN @ IP, using the callsign in that field and the PC's IP address.
  3. Contacts without a name use the picked Station. These include ADIF log files, ADIF over UDP from the relay's own PC, and WSJT-X/JTDX from that PC without --rig-name.
  4. With no station picked, unnamed contacts use the relay's name from the server's Relays page.

The server looks for a matching station name first, then a hostname, ignoring case. If neither matches, it creates a station if the person who enrolled the relay has manage-stations permission, or leaves the contact in the queue if they don't.

Step 5: Connect Your Logger

Use the subsection for your logger. Keep the relay running while you log.

Keep logger ports on the club network

Let other PCs connect and Let other PCs send contacts open listeners without passwords. Use them only on your club network. Never forward those ports from the internet.

N3FJP

Under N3FJP setup, click Turn on N3FJP if shown. For How should the relay connect to N3FJP?, choose the arrangement you use:

  • Join an N3FJP network server: enter N3FJP address, such as 192.168.1.5:1000, then click Save. Use 127.0.0.1:1000 if N3FJP's server runs on this PC.
  • Have N3FJP PCs connect here: turn on Let other PCs connect if N3FJP runs on other PCs. Set each N3FJP PC to TCP networking with the relay's computer as its server.

Use the N3FJP Network Status Display settings, substituting the relay's computer for the server in that guide. File Share mode won't work. N3FJP syncs contacts, edits, and deletes both ways.

When the relay acts as the N3FJP server, keep it running. Those N3FJP PCs don't keep their own log, and closing the relay stops logging.

N1MM Logger+

  1. Turn on Receive N1MM contacts in the relay.
  2. In N1MM's Entry Window, open Config > Configure Ports.
  3. Select the Broadcast Data tab.
  4. Check Contacts.
  5. Set the address to 127.0.0.1:12060.

For N1MM on other PCs, turn on Let other PCs send contacts and use the relay PC's address on port 12060. Contacts, edits, and deletes go to Field Day Commander. Nothing goes back to N1MM.

WSJT-X and JTDX

  1. Turn on Receive WSJT-X and JTDX contacts.
  2. Set your logger to send contacts by UDP to 127.0.0.1, port 2237.

If another program uses that port, change Port in the relay and click Save. Set the logger to the same port. GridTracker or JTAlert may already use 2237.

ADIF over UDP

  1. Turn on Receive ADIF contacts over UDP.
  2. Set your logger to send ADIF contacts by UDP to 127.0.0.1, port 2238.

For either UDP source on other PCs, turn on Let other PCs send contacts and send to the relay PC's address instead. WSJT-X/JTDX and ADIF over UDP send contacts one way, without edits or deletes.

ADIF Log Files

  1. Click Add log file.
  2. Choose the ADIF file your logger writes, such as wsjtx_log.adi.

You can watch up to 16 files. The relay only reads them. Deleting a contact from a file doesn't delete it from Field Day Commander. File reading needs a server connection first to learn the event's dates, then it can continue offline.

Step 6: Test a Contact

  1. Log a test contact in your logger.
  2. Check that Sent goes up in the relay.
  3. Find the contact in Field Day Commander's logbook.

Waiting counts contacts still queued. Rejected counts contacts the server refused. Read Contacts to check for the reason. Contacts outside the event's dates are refused, so check the practice event's dates before testing.

Self-Signed Certificates

This section is for whoever runs the server. The relay can't check a self-signed certificate automatically, so you need to compare its key with the server's. This confirms it's your club's server, not something pretending to be it.

Run this command on the server itself. See SSH Basics for opening a terminal. Replace both instances of fd.local with the name in the relay's Server address. Use port 443 unless that address specifies another port.

On the serverTerminal or SSH session
echo | openssl s_client -connect fd.local:443 -servername fd.local 2>/dev/null | openssl x509 -pubkey -noout | openssl pkey -pubin -outform der | openssl dgst -sha256

Compare the string after SHA2-256(stdin)= with Server's key in the relay. The command prints it without spaces. The relay splits it into groups of four characters. Check every group. If they match, click The keys match, connect. If they don't, don't connect until you've found the reason.

Troubleshooting

Needs https

Click Disconnect, then connect with the server's HTTPS address and a new code. If the server's Relays page says HTTPS required for relays behind a TLS proxy, ask the administrator to check TRUSTED_PROXIES.

That code didn't work

Create a new code on Relays. Codes work once and expire after 15 minutes.

Port busy

Another program is using the listener's port. For N1MM, close the program using UDP 12060. For WSJT-X/JTDX or ADIF, free the port or choose a different Port in the relay and match it in your logger.

Looking for N3FJP or Waiting for log

Check that N3FJP's network server is running and N3FJP address is correct. Select TCP networking in N3FJP's Settings > Network. File Share mode won't work.

Port blocked

In the relay's N3FJP server role, turn off N3FJP's own network server on that PC to free TCP 1000. The relay keeps trying.

This computer's clock differs from the server's

Check the clocks on the logging PC and server. A wrong PC clock can put contacts outside the event's operating period. Check the contact's date and time in your logger too.

This station isn't on the server

Pick a listed Station, or ask someone with manage-stations permission to create one matching the name or hostname in Contacts to check. Contacts stay queued until the station can be matched.
